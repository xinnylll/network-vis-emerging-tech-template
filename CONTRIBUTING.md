# Contributing in class

Create an issue before a substantial change. State the user task, observed problem, exact evidence location and proposed test. Make a branch in your working copy and a focused pull request. Rotate driver, analyst and reviewer. Each student explains one decision.

Run `npm run check`; preserve provenance and separate original, derived and generated fields. Include an accessible fallback. In the PR, link the issue, show the changed view, state the validation result and disclose assistance. A peer should be able to reproduce one claim from the README.

Do not put student identities, invitation lists, private reports, credentials or restricted data in the public repository. Keep the NEExT and struc2vec attribution with the airport data. Use the course’s private channel for access problems.
